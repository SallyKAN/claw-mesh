## 功能清单（6 项）

### P0 — 核心功能（Day 1-4）

#### 1. 节点远程命令执行（exec）
- Node 侧：`POST /api/v1/exec` handler，执行 shell 命令，返回 stdout/stderr/exit_code
- Coordinator 侧：`POST /api/v1/exec` 转发，支持指定节点或 auto-route
- Dashboard 集成：exec 结果显示在已有的聊天面板中
- 安全：`--allow-exec` flag 启用，默认关闭；后续加 allowlist
- 文件：`internal/node/exec_handler.go`, `internal/coordinator/exec_forwarder.go`
- 工作量：1 天

#### ~~2. Dashboard 聊天面板~~ ✅ 已有
- 已有完整聊天面板：chat panel + 消息列表 + 输入框 + 路由选择器 + 发送按钮
- 只需在现有面板中集成 exec 结果展示（随 exec 功能一起做）

#### 2. WebSocket 实时推送
- Coordinator → Dashboard 的 WS 连接
- 事件类型：node_online, node_offline, node_heartbeat, message_sent, message_response, exec_result, sync_update
- 文件：`internal/coordinator/ws_hub.go`, `internal/coordinator/events.go`
- 工作量：1 天

#### 3. Sync — 身份/记忆/Skills 跨机同步
- 同步范围：SOUL.md, IDENTITY.md, USER.md, MEMORY.md, memory/*.md, skills 目录
- 实现：
  - Coordinator 做中转站，维护文件 manifest（path + sha256 + mtime）
  - Node 每 30s pull manifest，对比本地 hash，增量下载变更文件
  - 上传：node 检测本地文件变更 → push 到 coordinator → 广播给其他节点
  - 冲突：双方都改了同一文件 → 保留双方（.conflict-{nodeId} 文件）+ 通知 dashboard
- API：
  - `GET /api/v1/sync/manifest` — 获取当前文件清单
  - `GET /api/v1/sync/file?path=xxx` — 下载单个文件
  - `POST /api/v1/sync/push` — 上传文件变更
  - `GET /api/v1/sync/status` — 同步状态（各节点最后同步时间）
- 文件：`internal/sync/manifest.go`, `internal/sync/server.go`, `internal/sync/client.go`, `internal/sync/watcher.go`
- 工作量：2 天

## 不做的（v0.3 Roadmap）

- Ed25519 节点认证（对标 mission-control）
- gRPC 通信（WebSocket → gRPC 可选）
- 任务分发系统（对标 SwarmClaw tasks/Kanban）
- 插件系统
- 多 coordinator 高可用
- 记忆图谱 / 时间衰减（SwarmClaw 级别的记忆系统）
- 身份连续性（跨 session 人格保持）

## 核心差异化叙事

SwarmClaw = "多个独立 OpenClaw 的管理面板"（Web UI，每个 agent 独立运行，手动配置每个 gateway/SOUL.md/记忆）

claw-mesh = "多台机器融合成一个 AI 助手"（CLI-first，`join` 一下就完事，身份和记忆自动同步，skills 自动共享）

这个叙事是护城河：SwarmClaw 的架构（每个 agent 独立 session + 独立存储）决定了它很难做到真正的跨机融合。

## 技术决策

- 语言：Go（已定，单二进制分发）
- 通信：HTTP + WebSocket（coordinator ↔ dashboard 用 WS，coordinator ↔ node 用 HTTP）
- 存储：文件系统（rules.json, manifest.json），不引入数据库
- 前端：原生 HTML/JS（已有 dashboard.html），不引入框架
- 同步：基于文件 hash 的增量同步，coordinator 做中转，不用 git/rsync
