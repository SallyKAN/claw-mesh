# Security

## Authentication

claw-mesh uses bearer token authentication:

- **Coordinator token** — generated by `claw-mesh init`, required for node registration and admin operations
- **Per-node tokens** — generated on registration, used for heartbeat and message forwarding

## SSRF protection

The coordinator validates all node endpoints to prevent SSRF attacks:

- Private IP ranges (`10.x`, `172.16-31.x`, `192.168.x`) are blocked by default
- Use `--allow-private` for LAN setups
- Loopback addresses are always blocked in production mode

## Recommendations

| Environment | Setup |
|-------------|-------|
| LAN / home lab | `claw-mesh up --allow-private` — private IPs allowed |
| Public internet | Use HTTPS (reverse proxy or TLS termination) + strong token |
| Mixed | WireGuard or Tailscale tunnel between nodes, then `--allow-private` |

## Token rotation

```bash
# Generate a new coordinator token
claw-mesh init --rotate-token

# Nodes will need to re-join with the new token
claw-mesh join <url> --token <new-token>
```

## Config seed security

The seed API transmits API keys over the network. Always use HTTPS when nodes connect over the public internet. See [Config Seed](/guide/config-seed) for details.
